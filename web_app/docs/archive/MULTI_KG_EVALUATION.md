# Multi-Knowledge Graph Evaluation Guide

## Overview

The NL2SPARQL system now supports evaluating performance across **multiple knowledge graphs**. This allows you to:

1. **Run the pipeline on different KGs** (e.g., copypu, DBpedia, custom RDFs)
2. **Automatically track which KG was used** for each evaluation
3. **Calculate overall system performance** across all KGs
4. **Compare per-KG performance** to identify KG-specific strengths/weaknesses

## Workflow

### Step 1: Configure Your Knowledge Graph

Update `config.yaml` with KG information:

```yaml
kg:
  name: "copypu"           # Your KG name
  source: "local_rdf"      # Type: local_rdf, sparql_endpoint, file
  ttl_file: "data/input/copypu.ttl"  # Path to RDF file
```

### Step 2: Run Evaluation on First KG

```bash
# GUI (auto-saves evaluation with KG tag)
python -m nl2sparql.gui_v2

# Or CLI with specific questions
python run_query.py "Which suppliers deliver Compensators?"
```

Results automatically include KG information:
```json
{
  "kg": "copypu",
  "kg_source": "local_rdf",
  "question": "...",
  "stages": {...}
}
```

### Step 3: Switch to Another KG

Update `config.yaml`:
```yaml
kg:
  name: "dbpedia"
  source: "sparql_endpoint"
  ttl_file: ""  # Leave empty for endpoints
```

Run more evaluations - they're automatically tracked separately.

### Step 4: Calculate Final Overall Accuracy

After all evaluations complete, run:

```bash
python evaluate_multi_kg.py
```

## Key Metrics

The evaluation tracks:

### Per-KG Metrics
- **Overall F1 Score**: Average F1 across all 4 pipeline stages
- **Class Extraction**: Precision, Recall, F1, Accuracy
- **Property Extraction**: Macro & Micro averages (Precision, Recall, F1)
- **Missing ID Extraction**: IRI resolution accuracy
- **Query Execution**: Result accuracy with row-based comparison

### System-Level Metrics
- **Overall System F1**: Average of per-KG F1 scores
- **KG Comparison**: Which KG performs best on which stages
- **Total Coverage**: Number of evaluations across all KGs

## Python API

```python
from evaluate_multi_kg import MultiKGEvaluationTracker

# Load all results
tracker = MultiKGEvaluationTracker()

# Get overall accuracy
overall = tracker.calculate_overall_accuracy()
print(f"System F1: {overall['overall_system_f1']:.4f}")

# Per-KG breakdown
for kg_name, kg_result in overall['per_kg_results'].items():
    print(f"{kg_name}: F1={kg_result['overall_f1']:.4f}")

# Save final report
tracker.save_final_report()
```

## Tips

1. **Keep KG names consistent** - Use same name for repeated evaluations on same KG
2. **Document source** - Set `kg_source` clearly (local_rdf, sparql_endpoint, etc.)
3. **Run evaluation regularly** - Call `python evaluate_multi_kg.py` after adding new results
4. **Compare per-stage performance** - Identify which pipeline stage needs improvement for each KG
5. **Track KG characteristics** - Note KG complexity, size, schema quality in kg_config.yaml

## Adding a New Knowledge Graph

1. **Add to `kg_config.yaml`**:
```yaml
- name: "my_new_kg"
  description: "Description"
  file: "path/to/file.ttl"
  enabled: true
```

2. **Update `config.yaml`**:
```yaml
kg:
  name: "my_new_kg"
  source: "local_rdf"
  ttl_file: "path/to/file.ttl"
```

3. **Run evaluations** on this KG

4. **Call tracker** to get updated metrics

## Troubleshooting

**Issue**: Results not showing up in multi-KG report
- **Solution**: Ensure `kg.name` is set in config.yaml before running evaluations

**Issue**: All results grouped as "default"
- **Solution**: Check that `kg.name` value matches in all evaluation runs

**Issue**: Different stage performance across KGs
- **Solution**: This is normal - compare per-KG stats to identify schema/size differences
